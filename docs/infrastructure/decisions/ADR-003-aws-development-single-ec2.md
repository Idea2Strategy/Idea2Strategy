# ADR-003: 개인 AWS의 단일 EC2 Development 환경

- 상태: Proposed
- 작성일: 2026-07-29
- 결정자: 인프라 담당자
- 관련 질문: INFRA-Q-003, INFRA-Q-006, INFRA-Q-010, INFRA-Q-012
- 관련 정본 ID: decision.dependencies.evidence-based, quality.auditability, quality.failure-safety
- Supersedes:

## 맥락

팀 통합 테스트와 외부 연동 검증을 위한 공용 Development 환경이 필요하다. 초기 서비스는 장애와 일시 중단을 허용하며, 실서비스 수준의 무중단·다중 리전·오케스트레이션은 요구하지 않는다. 프로젝트 지급 EC2는 2026년 8월 10일 이후 7일 이내 종료될 예정이므로 영속 환경으로 사용할 수 없다.

환경은 AWS Free Plan 기간의 PoC로 시작하되 Paid Plan 전환 뒤에도 같은 정의로 재생성할 수 있어야 한다. 운영 부담과 비용을 작게 유지하면서 측정된 병목에 따라 EC2 사양 상향, 작업자 분리 또는 수평 확장이 가능해야 한다.

## 선택지

### 선택지 A: 프로젝트 지급 EC2 사용

- 장점: 별도 초기 클라우드 비용이 없다.
- 단점: 종료일이 정해져 있고 계정·네트워크·복구 경로를 소유하지 못한다.
- 비용: 단기 비용은 낮지만 재이관 작업이 필요하다.
- 운영·보안·복구 영향: 장기 Development와 영속 데이터의 기반으로 사용할 수 없다.

### 선택지 B: 개인 AWS의 단일 EC2와 Docker Compose

- 장점: 단순하고 팀이 환경 수명주기와 확장 시점을 통제할 수 있다.
- 단점: EC2 장애 시 애플리케이션과 Redis가 함께 중단된다.
- 비용: EC2·EBS·EIP·Route 53·전송·관측 비용과 별도 RDS·S3 비용이 발생한다.
- 운영·보안·복구 영향: Terraform 재생성, SSM 접속과 최소 권한을 적용할 수 있다.

### 선택지 C: 초기부터 컨테이너 오케스트레이션 사용

- 장점: 다중 인스턴스와 배포 자동화 확장에 유리하다.
- 단점: 현재 부하와 운영 인력에 비해 구성요소와 장애 지점이 늘어난다.
- 비용: 관리형 제어 계층과 네트워크·관측 비용, 학습·운영 비용이 커진다.
- 운영·보안·복구 영향: MVP에서 필요성이 측정되지 않은 운영 복잡도를 선제 도입한다.

## 결정

인프라 담당자는 선택지 B를 선택했다. 팀 합의와 비용·복구 검증 전까지 이 ADR은 `Proposed`로 유지한다.

- 개인 AWS 계정의 서울 리전 `ap-northeast-2`에 공용 Development를 둔다.
- 애플리케이션·작업자·Caddy·Redis는 초기 단일 EC2의 Docker Compose에서 실행한다.
- 관계형 정본은 별도 RDS PostgreSQL, 대용량 불변 객체는 S3를 사용한다.
- 프로젝트 지급 EC2에는 영속 데이터와 배포·복구 경로를 의존시키지 않는다.
- AWS 리소스와 Route 53 레코드는 Terraform Community Edition으로 선언하고 원격 상태는 별도 S3에 보관한다.
- EC2 운영 접속은 Systems Manager Session Manager만 사용하고 공개 SSH를 두지 않는다.
- 외부 진입점은 `dev.ideatostrategy.com`이며 Caddy만 80·443을 공개한다.

## 근거

- 장애가 발생해도 수동 복구와 일시 중단을 허용하는 MVP 가용성 결정
- 모든 환경을 폐기 후 재생성할 수 있어야 한다는 인프라 담당자 결정
- 지급 EC2 종료 일정과 개인 AWS 기반 구조 유지 결정
- 2025년 7월 15일 이후 생성 계정에서 `t3.small`이 Free Tier eligible로 표시되는 AWS 공식 기준

## 결과와 영향

- 기대 효과: 가장 단순한 공용 환경으로 통합 검증을 시작하고 병목별 확장 경계를 유지한다.
- 감수하는 단점: EC2 단일 장애 지점과 수동 복구 시간이 존재한다.
- 구현·마이그레이션 순서: Terraform 상태 bootstrap → 네트워크·IAM·SSM → RDS·S3 → EC2·EIP → Route 53·Caddy → 애플리케이션 배포.
- 관측 및 검증: 최초 7일간 비용, CPU, 메모리, 디스크, CPU 크레딧과 API·작업자 간 영향을 측정한다.
- 롤백: 검증된 이전 이미지 조합을 재배포한다. EC2 손실 시 Terraform과 배포 아티팩트로 재생성하며 영속 복구는 RDS·S3 절차를 사용한다.
