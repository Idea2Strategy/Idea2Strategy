# ADR-008: 지원 종목 전체 SIP 공용 구독

- 상태: Proposed
- 작성일: 2026-07-29
- 결정자: 인프라 담당자
- 관련 질문: INFRA-Q-001, INFRA-Q-002, INFRA-Q-005, INFRA-Q-017, INFRA-Q-018, INFRA-Q-019
- 관련 정본 ID: policy.market.us-only, technology.need.market-data, quality.auditability, quality.failure-safety
- Supersedes:

## 맥락

실시간 SIP 데이터는 모의투자 주문·체결 판단, 가격·차트 표시와 개인 실시간 수익률 계산에 사용한다. 지원 범위는 S&P 500 구성 종목과 서비스가 관리하는 고정 주요 미국 ETF 목록이다.

실행 중인 봇과 현재 화면만 기준으로 구독 종목을 바꾸면 수신량을 줄일 수 있지만, 봇 시작·종료와 화면 이동 때마다 공급자 구독 상태를 변경해야 한다. 사용자별 외부 구독은 사용자 수만큼 연결·구독 상태가 증가하고 동일 종목 데이터가 중복될 수 있다.

## 선택지

### 선택지 A: 활성 수요 종목의 합집합만 구독

- 실행 중인 봇과 사용자가 보고 있는 차트에 필요한 종목만 서버가 구독한다.
- 수신량은 줄지만 구독 변경 경쟁, 첫 데이터 도착 전 공백과 구독 상태 복구를 관리해야 한다.

### 선택지 B: 정규장 동안 지원 종목 전체 구독

- S&P 500과 고정 주요 미국 ETF 지원 목록 전체를 서버 공용 스트림으로 구독한다.
- 사용자 활동과 외부 구독 상태가 분리되어 동작이 단순하고 모든 지원 종목의 최신 Hot Projection을 유지할 수 있다.
- 전체 Quote·Trade 처리량과 공급자 요금제 한도를 검증해야 한다.

### 선택지 C: 사용자 연결별 외부 구독

- 각 사용자 연결이 필요한 종목을 공급자에 별도로 구독한다.
- 사용자 수에 따라 외부 연결과 중복 구독이 증가하며 공급자 자격 증명·한도 관리와 장애 복구가 복잡해진다.

## 결정

인프라 담당자는 선택지 B를 선택했다. 팀 합의와 공급자 계약·부하 검증 전까지 이 ADR은 `Proposed`로 유지한다.

### 외부 SIP 구독

- 미국 정규장 동안 실시간 Market Data Worker가 지원 목록 전체를 하나의 서버 공용 구독 집합으로 유지한다.
- 봇 실행·종료, 사용자 로그인·로그아웃과 차트 화면 이동은 외부 구독 집합을 변경하지 않는다.
- 사용자 연결별 SIP 연결을 만들지 않는다.
- 지원 목록에는 버전을 부여하고 거래일별 적용 버전과 적용 시각을 기록한다.
- S&P 500 구성 변경과 ETF 목록 변경은 준비된 새 목록 버전을 거래일 경계에 적용한다.

### 내부 소비

- 실시간 Worker가 수신·검증한 전체 지원 종목 최신값을 Redis Hot Projection에 반영한다.
- 봇 실행기는 필요한 종목만 Redis에서 읽는다.
- `backend-app`은 차트 연결에 요청 종목만 전달한다.
- 개인 실시간 수익률은 화면을 보고 있는 사용자의 보유 종목만 계산한다.
- 내부 WebSocket 구독의 생성·종료는 외부 SIP 구독과 독립적이다.

## 장애와 데이터 경계

- SIP 연결이 끊기면 같은 지원 목록 버전의 전체 종목을 다시 구독한다.
- 재연결 중 누락 구간을 탐지하고, 가격 신선도 기준을 넘긴 종목은 최신값으로 가장하지 않는다.
- 가격이 유효하지 않은 동안의 모의투자 중지·주문 거절·사용자 경고 규칙은 별도 결정으로 확정한다.
- 실시간 원본 청크는 S3에 불변 객체로 저장하고, 지원 목록 버전·공급자·피드·세션·수집 세대를 매니페스트에 연결한다.
- Redis는 재구축 가능한 Hot Projection이며 실시간 시장 데이터의 영구 정본이 아니다.

## 결과와 영향

- 단순성 효과: 봇과 사용자 활동에 따라 외부 구독을 증감하는 상태 관리가 사라진다.
- 지연 효과: 지원 종목은 이미 구독 중이므로 새 봇이나 차트가 열릴 때 외부 구독 완료를 기다리지 않는다.
- 확장 효과: 사용자 수가 증가해도 SIP 외부 구독 수는 증가하지 않고 내부 WebSocket 전송만 증가한다.
- 비용·용량 영향: 지원 목록 전체의 Quote·Trade를 계속 처리하므로 네트워크, CPU와 Redis 갱신량이 커진다.
- 장애 영향: 단일 공용 SIP 연결 장애는 모든 실시간 모의투자와 차트에 영향을 주므로 신선도 감시와 안전 중지가 필요하다.
- 권리 영향: 공급자의 전체 종목 동시 구독, 서버 계산용 비표시 사용과 사용자 가격·차트 표시 권리를 계약에서 확인해야 한다.

## 확장과 롤백

서비스 EC2가 전체 지원 종목 스트림을 감당하지 못하면 먼저 실시간 Worker를 전용 EC2로 분리한다. 여러 서비스 호스트가 같은 Hot Projection을 읽어야 하는 시점에는 ElastiCache를 재검토한다.

공급자 한도나 비용 때문에 전체 구독이 불가능하면 새 ADR로 선택지 A의 활성 수요 합집합 구독을 검토한다. 이 경우 구독 참조 수, 변경 직렬화, 첫 데이터 준비 상태와 재연결 복구 규칙을 먼저 정의한다.

## 후속 작업

- [ ] SIP 공급자·요금제의 전체 지원 종목 동시 구독 한도 확인
- [ ] 비표시 계산과 사용자 가격·차트 표시 권리 확인
- [ ] Quote·Trade 채널별 초당 메시지, 네트워크, CPU와 Redis 부하 시험
- [ ] 정규장 전 연결 준비와 장 종료 후 구독 해제 시각 결정
- [ ] 지원 목록 버전 스키마와 거래일 경계 변경 절차 결정
- [ ] SIP 재연결·누락·지연 시 모의투자 안전 중지와 사용자 표시 규칙 결정
