# ADR-007: 리더보드와 개인 실시간 수익률 투영

- 상태: Proposed
- 작성일: 2026-07-29
- 결정자: 인프라 담당자
- 관련 질문: INFRA-Q-001, INFRA-Q-002, INFRA-Q-008, INFRA-Q-015, INFRA-Q-016, INFRA-Q-018
- 관련 정본 ID: journey.room.compare, policy.comparison.bots-only, quality.auditability, quality.reproducibility
- Supersedes:

## 맥락

모든 시장 데이터 틱마다 전체 사용자의 모든 성과와 리더보드를 다시 계산하면 사용자 수·봇 수·보유 종목 수에 비례해 CPU와 DB 부하가 증가한다. 반면 사용자가 자신의 봇·성과 화면을 보고 있을 때는 최신 가격을 반영한 개인 수익률을 빠르게 확인할 필요가 있다.

제품 정본에서 리더보드는 사용자를 직접 순위화하지 않고 방에 참여한 봇을 잠긴 점수 기준으로 비교한다. 따라서 “전체 사용자 계산”은 전체 참여 사용자의 순위 대상 봇을 계산한다는 의미로 적용한다.

## 선택지

### 선택지 A: 5분 전체 스냅샷과 화면 단위 실시간 투영 분리

- `batch-app`이 5분마다 전체 순위 대상 봇을 계산한다.
- 로그인 사용자가 해당 화면을 보고 있는 동안에만 개인 수익률을 실시간 계산한다.

### 선택지 B: 모든 대상의 수익률과 순위를 틱마다 계산

- 표시 지연은 가장 짧다.
- 화면을 보지 않는 사용자까지 계속 계산하므로 현재 규모에서 자원 사용량과 장애 범위가 불필요하게 커진다.

### 선택지 C: 모든 성과를 5분 스냅샷으로만 제공

- 구현은 가장 단순하다.
- 로그인 사용자가 자신의 현재 성과를 확인할 때도 최대 5분 지연이 발생한다.

## 결정

인프라 담당자는 선택지 A를 선택했다. 팀 합의와 제품 정본 반영 전까지 이 ADR은 `Proposed`로 유지한다.

### 전체 리더보드

- `batch-app`이 5분마다 전체 순위 대상 봇을 계산한다.
- 한 계산 주기는 동일한 평가 기준 시점, 가격 스냅샷, 원장·포지션 완전성 경계를 사용한다.
- 모든 대상 계산이 성공한 경우에만 새 스냅샷을 원자적으로 발행한다.
- 계산 실패 또는 지연 시 부분 순위를 공개하지 않고 이전 완료 스냅샷을 유지한다.
- 조회 화면에는 마지막 완료 시각 `calculated_at`을 표시한다.
- RDS의 완료 스냅샷이 조회 정본이며 Redis는 재구축 가능한 캐시로만 사용할 수 있다.

### 개인 실시간 수익률

- 로그인 사용자가 봇·성과 화면을 열 때 Frontend가 WebSocket 구독을 시작한다.
- `backend-app`은 해당 사용자의 RDS 공식 현금·포지션과 Redis 최신 가격으로 실시간 예상 수익률을 계산한다.
- 계산 결과는 해당 연결에만 전송하고 시장 데이터 틱마다 RDS에 저장하지 않는다.
- 화면 이탈, 로그아웃, WebSocket 종료 또는 유휴 만료 시 구독과 계산을 중단한다.
- 개인 실시간 예상값은 공식 리더보드 스냅샷을 변경하지 않는다.
- 화면은 공식 스냅샷 계산 시각과 실시간 가격 시각을 구분해 표시한다.

## 데이터와 실행 경계

- 공식 원장·현금·포지션: RDS
- 5분 리더보드 완료 스냅샷: RDS
- 최신 시장 가격과 개인 화면용 Hot Projection: Redis
- 장기 성과 시계열과 대용량 계산 증거: S3
- 전체 계산 실행: 백테스트·배치 EC2의 `batch-app`
- 개인 실시간 계산과 WebSocket: 모의투자 서비스 EC2의 `backend-app`

백테스트·배치 EC2는 Redis에 직접 접근하지 않는 기존 경계를 유지한다. 따라서 전체 계산에 사용할 동일 시점 가격 스냅샷을 내부 API, S3 불변 객체와 RDS 매니페스트 중 어떤 방식으로 전달할지는 후속 설계에서 확정한다.

## 결과와 영향

- 비용 효과: 화면을 보지 않는 사용자의 실시간 수익률 계산을 제거한다.
- 확장 효과: 전체 계산과 사용자 WebSocket 부하를 서로 다른 EC2에서 독립 확장할 수 있다.
- 일관성 효과: 리더보드는 한 주기 전체가 완료된 스냅샷만 보여주므로 부분 순위 노출을 막는다.
- 사용자 영향: 공식 리더보드는 최대 약 5분 주기로 갱신되고, 자신의 화면에서는 별도의 실시간 예상값을 볼 수 있다.
- 장애 영향: 배치 실패 시 이전 리더보드를 유지하며, 서비스 EC2 장애 시 개인 실시간 표시가 중단되더라도 공식 원장과 마지막 리더보드 스냅샷은 보존된다.

## 후속 작업

- [ ] 5분 계산의 정확한 기준 시각과 중복 실행 방지 규칙 결정
- [ ] 배치 EC2에 동일 시점 가격 스냅샷을 전달하는 경계 결정
- [ ] 리더보드 스냅샷 스키마·보존 기간과 원자적 발행 방식 결정
- [ ] 개인 WebSocket 갱신 빈도·유휴 만료·연결 제한 결정
- [ ] 공식 리더보드와 개인 실시간 예상값의 UI 표시 문구 검증
- [ ] 제품 정본에 5분 갱신 주기와 화면 단위 실시간 계산 정책 반영 요청
