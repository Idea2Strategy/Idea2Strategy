# Idea2Strategy UI 페이지 인벤토리

> 상태: 신규 UI 시안 제작을 위한 발견 문서
> 기준일: 2026-07-23
> 주의: 기존 `ui/`를 참고하거나 계승하지 않는다. 이 문서는 화면 책임과 필요한 정보의 범위를 정하며 최종 레이아웃·컴포넌트·색상값을 확정하지 않는다.

## 1. 서비스 이해

Idea2Strategy는 사용자가 미국 주식·ETF 가상 트레이딩 전략을 Basic 또는 Pro 시각 언어로 만들고, 불변 버전으로 출시한 뒤, 서버에서 봇을 실행하며 판단·주문·체결·포지션·공식 원장과 성과를 확인하는 서비스다. 출시 전략은 자동 공식 백테스트의 입력이 될 수 있고, 사용자는 별도의 방 참여 봇으로 객관적인 봇 간 비교에 참여할 수 있다.

사용자 화면은 다음 작업 순서를 중심으로 나눈다.

`전략 작성·출시 → 봇 구성·실행 → 운영 근거 확인 → 자동 백테스트 검토 → 방에서 봇 비교`

일반 사용자와 관리자는 계정과 화면을 분리한다. 웹 UI는 서버 기능을 조작하고 결과를 조회할 뿐 전략 평가·시세 수신·주문 실행을 담당하지 않는다.

## 2. 전체 정보 구조

### 비회원 영역

| 페이지 | 주된 목적 | 반드시 필요한 정보·행동 |
|---|---|---|
| 서비스 소개 | 제품 범위 이해 | 가상 미국 주식·ETF 봇, Basic·Pro 차이, 서버 실행, 실제 투자 아님, 시작하기·로그인 |
| 이용·법적 안내 | 오해 방지 | 모의투자 경계, 비추천 원칙, 데이터·성과 한계, 약관·개인정보 링크 |
| 가입·로그인 | 계정 진입 | 이메일 또는 지원 소셜 로그인, 오류, 이메일 확인 상태, 계정 복구 이동 |
| 이메일 확인 | 가입 완료 | 확인 대상, 만료·재발송 상태, 완료 후 이동 |
| 계정 복구 | 안전한 복구 | 복구 수단, 코드 입력, 실패·보호 상태, 로그인 복귀 |
| 첫 사용 안내 | 전체 흐름 이해 | Basic·Pro 차이, 작성·검증·출시·봇·백테스트·방 흐름, 실제 투자와 가상 체결의 차이, 건너뛰기·다시 열기 |

### 일반 사용자 전역 구조

- 상위 내비게이션: `전략`, `봇`, `백테스트`, `방`, `알림·사건함`
- 우측 계정 메뉴: 표시 언어, 테마, 계정·보안, 알림 설정, 로그아웃
- 상시 도움말: 현재 화면의 용어·지표·블록·노드·주문·예산·성과 계산 의미와 제한을 짧게 열고 전체 설명으로 이동
- 로그인 기본 진입점: `전략 > 작업본`
- 긴급한 계정·봇 조치가 있을 때만 전역 배너를 사용하며 성과 홍보 배너는 두지 않는다.
- 모바일은 조회와 봇 운영을 제공하되 Basic·Pro 전략 편집은 제공하지 않는다.

## 5. 백테스트 페이지

| 페이지 | 주된 목적 | 핵심 정보 | 주된 행동 |
|---|---|---|---|
| 자동 백테스트 목록 | 실행과 결과 찾기 | 연결된 출시 전략, 대기·실행·완료·실패·불가, 공식 기간과 생성 시각 | 필터, 결과 이동 |
| 백테스트 결과 | 공식 과거 재현 검토 | 전략 스냅샷, 기간·초기자본·모델 버전, 성과, 데이터·체결 한계, 실패·불가 이유 | ET 연·월 선택, 상세 자료 이동 |

결과 상세는 다음 영역으로 분리한다.

- `개요`: 핵심 성과, 평가 기간, 입력 전략, 데이터·비용 모델과 결과 상태
- `성과`: 자산 변화와 객관적 지표, 계산 기준
- `월별 판단 요약`: 최초 실패 조건별 월간 횟수
- `거래 상세`: 선택 월의 주문·개별 체결·취소·거절·비용·손익과 거래 후 현금·포지션
- `데이터·모델`: 사용 데이터, 누락 구간, 백테스트 한계와 버전

모든 상세 규칙을 첫 화면에 장문으로 펼치지 않는다. 결과 해석에 즉시 필요한 한계만 가까이 표시하고 전체 계산 근거는 `데이터·모델`에 둔다.

관리자는 사용자의 상세 전략 흐름·블록·노드·수식·임계값·위험 설정 원문을 열람하지 않는다.

## 10. 정보 밀도와 텍스트 원칙

### 한 페이지의 기본 구조

1. 페이지 제목과 현재 상태
2. 지금 필요한 주 행동 1개, 보조 행동 최대 2개
3. 첫 화면에서 판단에 필요한 핵심 정보 3~5개
4. 세부 정보는 목적별 탭·섹션·드로어로 분리
5. 오류·제한은 발생 위치 가까이에 짧게 표시하고 전체 근거로 이동할 경로 제공

### 텍스트 과다 방지

- 한 화면의 지속 노출 설명은 제목과 1~2문장 요약을 기본으로 한다.
- 정의·공식·모델 한계·법적 설명은 맥락 도움말이나 별도 상세 영역에 두되, 주문·출시·중단 결과를 바꾸는 핵심 경고는 접지 않는다.
- 긴 문단 대신 `라벨: 값`, 짧은 목록, 상태 배지, 표와 시계열을 사용한다.
- 표의 기본 열은 현재 작업에 필요한 5~8개로 제한하고 나머지는 상세 화면이나 열 설정으로 보낸다.
- 같은 설명을 카드·표·툴팁에 반복하지 않는다.
- Basic 블록과 Pro 노드에는 조작에 필요한 최소 텍스트만 둔다.

### 정보 부족 방지

- 빈 화면에는 `무엇이 없는지`, `왜 비어 있는지`, `다음에 할 수 있는 행동`을 함께 보여준다.
- 숫자에는 단위·기준 시각·데이터 상태를 가까이 표시한다.
- 상태만 보여주지 말고 사용자 조치 가능 여부와 다음 사건을 함께 보여준다.
- 요약 화면에서도 상세 판단 로그·공식 원장·계산 근거로 이동할 수 있어야 한다.

### 화면 분리 기준

- 목적과 주 행동이 달라지면 별도 페이지로 나눈다.
- 같은 객체를 서로 다른 관점으로 조회하면 탭으로 나눈다.
- 간단한 확인·선택은 모달이나 드로어를 사용할 수 있지만 전략 출시, 봇 실행, 방 생성처럼 많은 불변 설정을 검토하는 작업은 독립 단계로 둔다.
- 긴 단일 페이지 스크롤에 모든 상태와 전문 자료를 쌓지 않는다.

## 11. 라이트·다크 테마 방향

금융 화면에서 흔히 사용하는 `중립적인 밝은 표면 / 짙은 차콜 표면 + 파란 상호작용 + 녹색·적색 시장 의미` 구조를 출발점으로 삼는다. TradingView도 라이트·다크 테마와 파랑·회색·빨강·초록 등을 역할별 팔레트로 분리하지만, Idea2Strategy는 해당 제품의 화면이나 정확한 팔레트를 복제하지 않는다.

### 전략 편집기 의미색

- Basic `매수 전략`은 사용자 결정대로 붉은 계열을 우선한다.
- Basic `매도 전략`은 매수와 명확히 구별되는 별도 계열을 사용한다.
- 매수 색과 손실·오류 색이 같은 계열을 사용할 수 있으므로 색만으로 의미를 전달하지 않고 `매수` 이름, 감싸는 형태와 아이콘을 함께 사용한다.
- 시장 상승·하락, 주문 상태, 시스템 오류, 매수·매도, 방 순위는 서로 다른 의미 토큰으로 관리한다. 같은 색상값을 쓰더라도 이름과 표현 규칙을 합치지 않는다.
- 차트와 테마는 함께 전환해 밝은 앱 안에 어두운 차트가 남거나 반대가 되지 않게 한다.

일반 본문 텍스트는 배경과 최소 `4.5:1`, 큰 텍스트는 최소 `3:1` 대비를 만족시킨다. 의미 있는 조작 요소의 윤곽은 인접 배경과 최소 `3:1`을 확보하고 장식용 경계선과 구분한다. 색만으로 상태를 구분하지 않으며 정확한 후보 색상은 시안별 대비 검사 후 바꿀 수 있다.

## 12. 후속 시안 비교 방법

동일한 페이지 범위와 정보를 사용해 다음처럼 시각적 성격이 다른 안을 만들 수 있다.

1. `균형형`: 일반 SaaS의 명확한 여백과 금융 정보 밀도를 절충
2. `터미널형`: 표·차트·빠른 탐색을 강화하되 텍스트 설명은 접어서 제공
3. `캔버스형`: 전략 편집기의 블록·노드 작업 공간을 최대화하고 주변 정보를 필요할 때 열기

각 안은 대표 여정인 `Basic 전략 생성`, `Pro 전략 생성`, `봇 운영`, `백테스트 검토`, `방 참여`를 같은 데이터와 상태로 제작해 비교한다. 전체 사이트가 서로 다른 구조가 되지 않도록 전역 내비게이션과 페이지 책임은 유지하고 레이아웃·밀도·색상·컴포넌트 표현을 비교한다.

## 13. 아직 확정하지 않는 항목

- 정확한 라우트 이름과 URL
- 페이지·탭·모달의 최종 배치
- 최종 색상값, 글꼴, 간격, 아이콘과 디자인 토큰
- 전략 편집기의 패널 크기·위치와 캔버스 조작 세부값
- 데스크톱 최소 화면 크기와 모바일 전환점
- 표의 열 구성과 차트 유형
- 온보딩·도움말의 정확한 문구와 매체
