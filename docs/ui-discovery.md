# Idea2Strategy UI 발견 인벤토리

## 문서 역할

- 이 문서는 `product-discovery.md`에서 확정한 제품 의미를 빠짐없이 화면 후보와 사용자 상태로 옮기기 위한 발견 자료다.
- 현재 UI 상태는 `신규 기준선 발견 중`이다. 상위 정보 구조, 화면별 책임, 필수 정보·상태·행동과 금지 표현 및 아래의 Basic·Pro 편집 상호작용은 확정하지만 실제 화면을 만들어 보아야 판단 가능한 시각 설계는 확정하지 않는다.
- 화면 배치, 디자인 시스템, 컴포넌트 구조, 라우팅, API, DB와 구현 기술을 확정하지 않는다.
- 저장소의 기존 `ui/` 서브모듈은 참고·시드·최종 명세로 사용하지 않는 폐기 대상이다. 실제 제거는 별도 검토된 저장소 변경으로 수행한다.
- 동일한 제품 의미를 여러 UI 안으로 시각화해야 판단 가능한 항목은 미리 고정하지 않고 `UI 비교 필요`로 남긴다.
- 정확한 화면 설계는 프로젝트 하네스와 편집 가능한 UI 작업공간이 준비된 뒤 실제 대표 화면·상태를 시안으로 만들어 다시 검증한다.
- 그 단계에서는 당시 사용 가능성과 출처를 확인한 UI 설계 Skill을 활용할 수 있으며 MengTo/Skills와 같은 도구도 후보에 포함한다. 특정 Skill 이름이나 현재 출력물을 최종 UI 권위로 미리 고정하지 않는다.
- UI Skill이 새로 만든 결과는 제안 자료다. 확정된 제품 의미·접근성·한국어와 영어·데스크톱과 모바일·법적 금지 경계를 대조하고 사용자가 승인한 새 기준선만 후속 프런트엔드 설계의 입력으로 사용한다.
- 페이지별 책임, 필요한 정보, 텍스트 밀도와 라이트·다크 테마 출발 방향은 [`ui-page-inventory.md`](ui-page-inventory.md)에 정리한다. 이 인벤토리는 여러 신규 시안이 같은 제품 범위를 표현하도록 하는 비교 기준이며 최종 레이아웃은 아니다.

## 확정된 공통 진입 구조

- 데스크톱 로그인 기본 진입점은 `전략`이다.
- 일반 사용자 상위 영역은 `전략`, `봇`, `백테스트`, `방`, `알림·사건함`으로 분리한다.
- 계정·보안·표시 언어·알림 설정은 별도 계정 메뉴에서 제공한다.
- 모바일은 조회와 봇 운영을 지원하지만 Basic·Pro 전략 편집은 시작하거나 이어갈 수 없다.
- 관리자·운영자는 일반 사용자 UI와 계정이 완전히 분리된 관리자 전용 화면을 사용한다.
- 한국어와 영어에서 동일한 기능을 제공하고, 모든 사용자 대면 시각은 ET, 금액은 USD로 표시한다.

- 새 기기 로그인 통지, 현재 세션, 다른 활성 세션, 원격 종료 성공·실패
- 계정 일시 정지·영구 제재 시 일반 기능 차단과 이의제기·법적 권리용 최소 접근

## 전략 영역

### 전략 라이브러리

`작업본`, `출시된 전략`, `재사용 컴포넌트`, `플랫폼 템플릿`을 별도 탭으로 제공한다.

각 탭은 다음 상태를 구분해야 한다.

- 항목 없음, 검색 결과 없음, 로딩, 조회 실패
- Basic·Pro
- 저장됨·미저장 변경·저장 중·저장 실패
- 미검증·검증 통과·검증 무효화·검증 실패·확인 필요 경고
- 출시 후 자동 백테스트 가능·일부 블록 때문에 출시 후 자동 백테스트 불가
- 출시 가능·출시 차단·출시됨·보관됨
- 현재 편집 접속 사용 중·추가 편집 접속 차단

### 새 전략 시작

- 빈 Basic 작업본
- 빈 Pro 작업본
- 플랫폼 템플릿에서 새 작업본 생성
- 자신의 기존 전략을 복사해 새 작업본 생성
- Basic 원본을 보존하고 새 복사본을 Pro로 변환
- 구버전 의미 유지 복사 또는 최신 카탈로그 변환 복사

어떤 진입점도 종목·수치·전략·예산·위험 설정을 추천하거나 숨겨진 값으로 채우지 않는다.

### Basic 편집기

- 선 없이 Scratch처럼 직접 맞물리는 순차 퍼즐 블록과 드롭다운·타입 지정 동적 입력을 사용한다.
- 최상위에는 내부 흐름을 감싸는 `매수 전략`과 `매도 전략` 메인 블록을 두고 이름·형태·서로 다른 색상으로 멀리서도 구분한다. 매수는 붉은 계열을 우선 사용하되 정확한 색상값은 새 시안에서 검증한다.
- 개별 블록에는 지표명·연산자·입력값처럼 조작에 필요한 최소 텍스트만 둔다. 완성된 블록 묶음에 호버하면 각 블록 옆에 해당 부분의 규칙 기반 자연어가 나타나고 위에서부터 이어 읽으면 전체 전략 문장처럼 검토할 수 있다.
- 플랫폼 템플릿은 매수·매도로 구분한다. 지표 검색 결과에는 상승·하락을 조건으로 매수·매도하는 단순 구조와 알려진 지표 기반 이론 구조를 제공하되, 종목·기간·임계값·비율 등 세부 값은 모두 비워 둔다.
- 종목별 독립 평가, 균등 배분과 Basic이 허용한 제한된 정책만 편집할 수 있다.
- 블록 추가·삭제·순서 변경과 매개변수 입력, 현재 위치의 도움말을 제공한다.
- Pro 전용 분기·다중 입력·다종목 관계·사용자 정의 수식을 Basic에서 우회 입력할 수 없다.

### Pro 편집기

- 타입 지정 노드, 연결, 분기·병합, 제한된 목록 연산, 재사용 컴포넌트와 최종 주문 처리 구조를 시각적으로 편집한다.
- 좌우 연결을 기본으로 하고 노드 의미에 따라 둘 이상의 타입 지정 출력 포트를 제공한다. 일반 노드의 세부 설정과 출력 포트로 표현할 수 있으므로 정확한 노드 수와 카탈로그는 후속 검증에서 정한다.
- 연결 가능한 노드·포트는 활성화하고 연결 불가능한 대상은 비활성화한다. 비활성화 사유를 개별 설명하는 기능은 요구하지 않는다.
- 연결선을 빈 공간에 놓기 위해 마우스 버튼을 뗀 지점에 해당 출력과 호환되는 노드만 모은 카테고리형 선택창을 연다.
- 금융공학·퀀트·투자 이론에서 알려진 병렬·페어 트레이딩 등의 구조 템플릿을 제공하되 모든 세부 값은 비워 두며, 빈 캔버스 시작도 제공한다.
- 뒤로 돌아가는 순환·일반 반복문·임의 코드 입력은 제공하지 않는다.
- 모든 주문 후보 경로가 정확히 하나의 최종 주문 처리 블록에 합류하는지를 확인할 수 있어야 한다.
- 실행 중 어떤 노드가 돌아가는지 실시간으로 애니메이션하거나 중간 계산 결과를 공식 결과처럼 노출하지 않는다.

### 저장·검증

- 자동 저장하지 않는다. 사용자가 저장할 때만 서버의 현재 작업본 하나를 갱신한다.
- 저장 중·성공·실패·마지막 성공 시각과 미저장 변경을 항상 구분한다.
- 작업본에서는 백테스트 실행 행동을 제공하지 않는다. 미저장 변경 상태에서는 검증·출시를 실행하지 않는다.
- 편집 중 사전 진단과 사용자가 요청하는 공식 서버 검증을 구분한다.
- 검증 결과는 전체 요약과 문제 위치를 연결하고 출시 차단 오류·확인 필요 경고·객관적 정보를 구분한다.
- 검증은 투자 위험·전략 품질 점수가 아니며 오류를 자동 수정하지 않는다.

### 출시 흐름

- `전략`에서 현재 작업본을 선택해 시작하거나 `봇`에서 새 봇 만들기로 시작해도 같은 출시 절차를 사용한다.
- 방 참여는 이미 운영 중인 개인 봇을 선택하는 절차가 아니라, 선택한 전략·설정을 복사해 독립된 새 방 참여 봇 객체를 만드는 절차로 제공한다.
- 하나 이상의 저장·검증된 전략, 종목·종목군, 전략별 예산 상한, 자금 충돌·배분 정책, 포트폴리오 위험 설정, 시작 자본과 비용 입력을 검토한다.
- Basic·Pro 필수 정책 누락, 동시 운영 봇 10개 상한, 계정·방 자격과 데이터 가용성을 확인한다.
- 최종 확인 시 정확한 전략·컴포넌트 버전과 봇 구성을 한 번에 잠그고, 개인 봇은 실행하며 방 참여 봇은 방 일정에 따라 대기하거나 공식 평가를 시작한다.
- 일부만 잠그거나 실패한 봇·원장·슬롯을 남기지 않는다.

## 봇 영역

### 목록과 필수 상태

- 실행 중, 조치 필요, 중단 처리 중, 중단, 보관됨
- 개인 봇, 방 제출 대기, 방 평가 중, 방 소속 없음
- 정상, 시장 폐장 대기, 데이터·기업행사 확인 중, 주문·정산 처리 중
- 동시 운영 10개 사용량과 새 봇 실행 가능 여부
- 계속 실행 확인이 필요한 무소속 개인 봇의 현재 기한, 알림 전달 상태와 봇별 `30일 연장`·`계속 실행` 명시적 행동
- 연장 요청을 서버가 정상 접수할 때 새로 설정될 정확한 기한. 로그인·화면 조회·알림 열람·이메일 수신은 연장 행동으로 표현하지 않는다.
- 현재 확인 기한은 항상 표시하고, `30일 연장` 버튼은 기한 7일 전부터 기한 직전까지만 활성화한다. 그 전에는 다음 활성화 시각을 보여주며, 활성화 구간의 정상 접수 시각부터 30일 뒤로 이동할 새 기한을 행동 전에 명확히 표시한다.

### 상세 화면 필수 정보

- 잠긴 봇 구성과 연결된 전략·컴포넌트 버전
- 실행 상태, 시작·중단 시각과 조치 필요 사유
- 가상자금, 전략별 예산 상한·사용액, 포지션과 미체결 주문
- 최근 판단과 주문·체결 상태
- 판단 로그, 공식 원장, 성과와 데이터 기준 시각
- 판단 로그는 결과가 발생한 평가만 표시한다. 단순 조건 불충족만 있었던 시간대에 로그가 없는 상태를 데이터 누락·서버 장애로 표시하지 않고, 실제 평가 오류나 장애 사건과 구분한다.
- 방 소속·평가 구간·공개 기준 충족 여부
- 일반 실행 중 사용자가 수행하는 수명주기 제어인 `중단`, 무소속 실행 봇의 명시적 `30일 연장`, 방 평가 중의 종료 후 계속 실행 선택

### 첫 화면 정보 우선순위

- 봇 상세의 기본 진입 화면은 `운영 개요`로 두고 실행 상태와 조치 필요 항목을 가장 먼저 보여준다.
- 같은 첫 화면에서 가용자금, 전략별 예산 사용, 현재 포지션과 미체결 주문을 핵심 운영 상태로 이어서 제공한다.
- 성과는 별도 `성과` 영역에서, 판단 로그와 공식 원장은 각각의 상세 영역에서 조회한다. 첫 화면에는 현재 상태를 이해하는 데 필요한 요약과 해당 상세로 이동하는 연결만 둔다.
- 이 우선순위는 성과를 숨기거나 판단 로그 접근을 약화하는 의미가 아니며, 긴급 조치 누락과 성과 중심 투자 추천처럼 보일 위험을 줄이기 위한 정보 구조다.
- 정확한 카드·표·탭 배치, 정보 밀도와 반응형 전환은 실제 시안에서 검증한다.

## 백테스트 영역

### 화면 후보

1. 실행 목록과 상태
2. 출시 전략별 자동 백테스트 실행 상태
3. 자동 실행 대기·진행·완료·실패·백테스트 불가
4. 결과 상세
5. 연결된 전략 스냅샷과 ET 월별 판단 요약·거래 상세

### 반드시 표현할 상태

- 출시된 불변 전략 버전만 자동 백테스트 대상이라는 입력 출처와 자동 실행을 발생시킨 출시 사건
- 사용자가 변경할 수 없는 플랫폼 공식 백테스트 설정의 ET 출시 분기, 새 분기 직전의 완전한 3개 달력연도로 고정되고 분기마다 한 분기씩 이동하는 평가 시작일·종료일, `USD 10,000` 시작 가상자본, 수수료·슬리피지와 설정 버전. 같은 분기에 생성된 모든 불변 출시 전략 버전에는 같은 평가 기간과 시작 자본이 적용되고 중립적인 재현 환경이지 추천값이 아니라는 설명
- 전략의 고정 금액 입력을 백테스트 자본에 맞춰 자동 조정하지 않으며 자금 부족으로 주문이 거절·축소될 수 있다는 설명과 해당 판단 기록
- 모든 종목·시각·주문 크기에 체결 한 방향당 동일하고 사용자가 변경할 수 없는 `0.05%` 고정 슬리피지, 매수에는 더하고 매도에는 빼는 불리한 적용 방향, 지정가 등 주문 가격 제한을 넘겨 체결하지 않는 규칙
- 거래별 슬리피지 적용 전 기준가격·고정 비율·슬리피지 금액·최종 체결가격과 실제 시장의 보편적 평균이 아니라 단순화된 플랫폼 공식 가정이라는 설명
- 모든 매수·매도와 롱·숏 개별 체결에 동일하고 사용자가 변경할 수 없는 체결금액의 `0.2%` 통합 수수료, 슬리피지 반영 후 체결금액을 기준으로 부분 체결마다 계산하는 규칙
- 거래별 수수료 기준 체결금액·`0.2%` 비율·최종 수수료, SEC·FINRA와 브로커별 비용을 별도로 더하지 않으며 실제 업계 평균이 아닌 보수적인 플랫폼 공식 가정이라는 설명
- 완료된 1분봉으로 만든 주문은 같은 봉에 소급 체결되지 않고 다음 유효한 미국 정규장 1분봉부터 체결 가능하다는 설명. 시장가는 다음 유효 봉의 시가를 최초 기준가격으로 사용한다.
- 일반 거래일 마지막 봉의 신호는 다음 정규장부터 체결 가능하고 DAY도 그 세션에 적용되며, 공식 평가 기간 마지막 봉의 후보는 기간을 연장하지 않고 `평가 기간 종료` 미체결로 남는다는 설명
- 거래 상세의 신호 시각·신호 봉·주문 후보 생성 시각·최초 체결 가능 시각·실제 체결 평가 봉·사용 가격 필드
- 개별 1분봉 누락 시 해당 구간에서만 평가·발동·체결을 건너뛰고 백테스트를 계속한 결과, 누락 구간·영향 종목·건너뛴 평가·영향받은 주문과 데이터 복구 후 현재 시점부터 재개했다는 설명
- 전략이 요구하는 데이터 종류·시간 해상도 자체가 없어 전체 `백테스트 불가`가 된 경우와 개별 데이터 공백을 명확히 구분
- 공식 자동 백테스트에는 1분봉 거래량 대비 주문 참여율 상한이 없으며, 유효한 양의 거래량 봉에서 다른 공식 조건을 통과한 남은 체결 가능 수량 전부가 체결될 수 있다는 설명
- 거래량 `0`인 봉은 미체결, 누락·불완전 봉은 데이터 공백으로 구분하고, 거래 상세에는 봉 거래량·요청 수량·체결 가능 수량·최종 체결 수량과 `거래량 참여율 상한 미적용`을 표시
- 거래량 때문에 주문을 나누어 체결하지 않는 단순화가 대규모·저유동성 주문 결과를 실제보다 낙관적으로 만들 수 있으며 실시간 서버 봇의 거래량·부분 체결 정책과는 다르다는 모델 한계
- 한 1분봉에서 서로 배타적인 주문 조건이 함께 충족된 경우 시가에서 발동 가격까지의 절대 거리가 가까운 주문을 먼저 처리하고, 거리가 같으면 불리한 주문을 먼저 처리했다는 봉 내부 순서 가정
- 출시 전략 버전당 자동 백테스트는 최대 한 번이며 완료·실패·백테스트 불가 뒤에는 같은 버전을 재실행할 수 없다는 상태
- 대기·실행 중인 자동 백테스트에는 취소 행동을 제공하지 않고 브라우저 종료와 관계없이 서버에서 계속 처리됨을 표시
- 자동 백테스트 실행과 완료·실패·백테스트 불가 결과에는 삭제·보관·숨김 행동을 제공하지 않는다. 연결된 출시 전략이 보관돼도 해당 결과는 계속 조회할 수 있게 한다.
- 백테스트 미지원 블록과 전략 전체 실행 차단 사유
- 공식 평가 시작일보다 늦게 상장된 대상 종목이 하나라도 있어 전략 전체가 `백테스트 불가`가 된 경우 해당 종목·상장일·필요 시작일. 부분 기간 실행이나 자동 종목 제외는 제공하지 않는다는 설명

## 알림·사건함

### 알림

- 끌 수 없는 필수 운영 알림과 사용자가 선택하는 일상 판단·주문·체결 알림을 구분한다.
- 선택형 일상 판단·주문·체결 알림은 처음에 모두 꺼진 상태로 표시하고 사용자가 봇별·사건별로 명시적으로 켜게 한다.
- 앱 내 알림과 이메일 전달 상태는 공식 전략·주문·원장 결과와 구분한다.
- 알림은 객관적 사실과 필요한 사용자 행동만 전달하고 매수·매도·보유 제안이나 위험 등급을 포함하지 않는다.

### 사건함

- 문의·신고·이의제기는 구조화된 일회 제출로 처리한다.
- 상태는 접수·검토 중·처리 완료·처리 불가를 구분한다.
- 사용자는 서버 사건 참조값과 객관적 설명을 제출하며 파일·전략 원문·수식은 제출하지 않는다.
- 사건을 수정하거나 운영자와 채팅하지 않는다. 자료가 부족하면 결과를 확인하고 이전 사건 번호를 참조해 새 사건을 제출한다.
- 이메일은 상태 변경 사실만 알리고 서비스 내부 결과를 사건 기록의 정본으로 사용한다.

- 한국어·영어 문구 길이 차이, 키보드·스크린리더·색상 외 상태 전달

## 하네스 UI 시안 단계까지 확정하지 않는 항목

- 각 상위 영역의 카드·표·탭·패널 배치와 정보 밀도
- Basic 블록 팔레트와 Pro 노드 그래프의 세부 패널 배치·크기·밀도
- 데스크톱 최소 해상도와 모바일 전환 지점
- 색상·타이포그래피·간격·아이콘과 디자인 시스템
- 숫자 표시 정밀도와 긴 수치의 축약 방식

위 항목은 현재 제품 발견의 누락이 아니다. 하네스에서 대표 사용자 여정과 정상·대기·빈 상태·오류·권한 없음·처리 중·완료 상태를 새 화면으로 비교한 뒤 확정하며, 기존 UI는 비교안이나 기준선 입력으로 사용하지 않는다.

## UI에서 사용하지 않을 표현과 동작

- 특정 종목·전략·수치·비중·주문 행동 추천
- 전략·봇의 안전·위험·우수·열등 등급
- 사용자 간 비교, 다른 사용자의 상세 전략·보유·거래 노출
- 백테스트 수익을 출시 승인이나 미래 성과 보장처럼 표시
- 실행 중인 전략 노드의 실시간 진행 애니메이션
- 사용자가 개별 주문이나 주문 의도를 직접 제출하는 입력
- 브라우저·모바일을 로컬 봇 실행기처럼 표현하는 상태
- 수정 가능한 것처럼 보이는 잠긴 전략·공식 원장·확정 성과 편집 기능
