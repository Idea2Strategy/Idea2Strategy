# 제품 발견 근거 자료 (비정본)

> 이 파일은 회의록과 참고 자료에서 확인한 배경을 보존한다. 현재 제품 의미의 정본은 [`product-discovery.md`](product-discovery.md)이며, 이 파일의 제안과 충돌하면 정본을 우선한다.

## 회의록에서 반복적으로 확인된 문제와 원칙

아래 내용은 현재 방향과 잘 맞지만, 사용자가 직접 재확인하지 않은 항목은 아직 확정 결정이 아니다.

- 전략 작성과 생성된 봇의 운영·성과 화면을 분리한다.
- 서비스의 중심은 일반 주식 거래 화면이 아니라 전략의 판단, 행동, 근거를 검증하는 경험이다.
- 체결된 주문뿐 아니라 주문하지 않은 판단도 기록해 사용자가 이유를 추적할 수 있게 한다.
- 블록·노드 연결은 입력·출력 타입과 실행 순서를 기반으로 결정론적으로 검증한다.
- 논리적으로 도달할 수 없는 조건, 누락된 값과 상충 조건을 실행 전에 알려준다.
- 특정 종목, 비중, 임계값과 매매 방향을 서비스가 임의로 추천하지 않고 사용자가 직접 정한다.
- 성과는 수익률 하나로 추천 순위를 만들기보다 최대 낙폭, 변동성, 샤프지수, 승률, 거래 횟수와 운영 기간 등을 함께 보여주는 방향이 반복 제안됐다.
- 모의투자는 실제 시장과 동일한 결과를 보장하지 않으며 데이터 지연, 수수료, 슬리피지, 기업행사와 거래 가능 시간의 한계를 명확히 다뤄야 한다.

## 회의록에서 드러난 방향 변화

### 초기·과거 방향

- 자연어 프롬프트와 내부 LLM이 전략을 구성하는 방안이 중심이었던 기록이 있다.
- `[과거 제안]` 로컬에서 봇을 실행하거나 사용자가 봇을 다운로드하는 구조도 논의됐으나 최신 결정으로 폐기됐다.
- 장기 포트폴리오형과 단기 매매형, 한국 종목 예시와 미국 종목군 예시가 함께 등장했다.

### 이후 구체화된 방향

- 2026-07-15 기록에서는 서비스 내부 AI 호출보다 블록 UI와 외부 AI/CLI 연동을 강조했다.
- 2026-07-16 기록에서는 Basic의 Scratch형 블록과 Pro의 노드 그래프, 결정론적 규칙 검사, 전략 편집과 봇 운영의 분리가 더 구체화됐다.
- 현재 대화에서는 내부 AI나 CLI보다 Basic/Pro 노코드 작성과 미국 주식·ETF 기반 라이브 가상 운영이 명시적으로 선택됐다.
- 최신 결정에서는 봇 운영 전체를 Idea2Strategy 서버의 책임으로 확정했으며, 클라이언트 주문 의도·로컬 실행기·Heartbeat·로컬 봇 대안은 현재 제품 방향에서 폐기됐다.

따라서 초기 AI 중심 문구, 로컬 봇 다운로드·실행, 클라이언트 주문 전송과 특정 기술 스택은 현재 제품의 확정 사항으로 간주하지 않는다.

## 회의 자료별 요약

### `회의록_0710_1500_공유본.pdf` - 2026-07-10

- 사용자가 전략과 수치를 정하고 AI는 조건을 구조화한다는 안전선을 논의했다.
- `[과거 제안]` 클라이언트가 주문 의도만 보내고 서버가 공통 시세와 서버 시간으로 가상 체결·공식 원장을 관리하는 안을 제시했으나 최신 결정으로 폐기됐다.
- 다른 사용자의 전략 복제·판매와 종합 추천 랭킹은 제외하는 방향이었다.
- 공식 방은 동일 조건에서 여러 객관적 지표로 비교하는 검증 환경으로 정의했다.
- 로컬 봇 다운로드는 최신 서버 전용 실행 결정으로 폐기됐고, AI 중심 작성도 현재 방향과 맞지 않는 과거 안이다.

### `AI 트레이딩 봇 프로젝트 회의 정리.pdf` - 날짜 미표기

- 자연어 프롬프트, 선택형 입력과 LLM 전략 생성을 중심으로 한 초기 구상을 정리했다.
- 장기 포트폴리오형과 단기 트레이딩형을 구분하고 백테스트는 참고 기능으로 보는 의견이 있었다.
- Redis 실시간 캐시, RDB/S3 역할 분리와 구독 종목 관리 아이디어가 제안됐다.
- `[과거 미결]` AI 추천의 법적 위험, 데이터 저장 기간과 봇 실행 위치가 당시에는 미결이었으나, 현재 봇 실행 위치는 서버로 확정됐다.

### `B205_멘토_피드백_전체내용_상세정리.pdf` - 2026-07-14

- Scratch형 조합과 충돌 방지는 긍정적으로 평가됐다.
- 백테스트, 라이브 모의투자와 대회가 섞여 핵심 가치가 모호하다는 지적이 핵심이었다.
- 팀은 라이브 모의투자가 주 목표이고 백테스트는 참고용이라고 답했다.
- 수 초 수준의 지연은 가상 운영에서 허용 가능하다는 의견이 있었다.
- 단순 기술지표만으로 차별화하기 어렵고 전략 범위, 데이터 확보와 차트 구현을 조기에 검증해야 한다는 조언이 있었다.
- 페어 트레이딩·통계적 차익거래 등 금융공학은 MVP 확정 요구가 아니라 향후 전략 깊이를 결정하기 위한 학습 방향으로 제안됐다.

### `B205_법적_리스크_및_대응.pdf` - Version 2.0, 2026-07

- 순수 모의투자 구조를 전제로 형법·사행행위 규제, 자본시장법, 저작권법·부정경쟁방지법, 개인정보보호법, 전자금융거래법과 표시·광고 관련 법률을 검토한 내부 초안이다.
- 실거래·자금 보관·중개·투자 추천을 하지 않고 모의 잔고에 환전·양도·결제 기능을 두지 않는 제품 경계를 제안한다.
- 공식 데이터 이용권, 저장·가공·표시·백테스트·가상 체결·비교 권한 확인과 무단 크롤링·보호조치 우회 금지를 요구한다.
- 전략·포트폴리오·거래 기록 비공개, 개인정보 최소 수집, 접근 통제·기록과 목적 종료 후 삭제를 제안한다. 관리자 상세 전략 열람은 최신 결정에서 이 문서보다 더 엄격하게 금지한다.
- 성과는 기간·비용·위험 지표와 함께 표시하고 수익 보장, 실거래 재현 보장과 추천성 순위를 금지하는 방향이다.
- 문서의 `서버에 실시간 접수된 모의주문`은 과거 표현이며, 최신 결정에 따라 서버가 잠긴 전략을 직접 평가해 주문을 생성하는 구조로 대체한다.
- 이 문서는 전문 법률 자문이 아니며 기능·과금·보상·데이터 계약·개인정보 처리 구조가 바뀌면 재검토해야 한다.

### `회의록_0715_1300.pdf` - 2026-07-15

- Alpaca 데이터 수집과 미국 종목 데이터의 시간대·세션·결측 문제를 논의했다.
- 초보용 단순 모드와 전문 기능을 제공하는 상세 모드 분리가 선호됐다.
- Scratch형 퍼즐, 큐브·보드, 노드형 구조를 비교했고 복잡성과 표현력의 균형이 핵심 쟁점이었다.
- 블록 UI와 CLI, 실시간 가상 운영, 판단 근거 로그, 성과 비교가 현황표에 반영됐다.
- React, Spring Boot, FastAPI, PostgreSQL, Redis, S3, AWS 등이 기록됐지만 역할과 최종 구조는 서로 충돌하거나 미정이었다.

### `회의록_0716_13.pdf` - 2026-07-16 13시

- 전략 편집과 봇 운영을 분리하고 전략 판단·근거 검증을 중심에 두는 방향이 강하게 합의됐다.
- Basic=Scratch형 블록, Pro=노드 그래프가 유력해졌고 타입 포트, 실행 순서와 논리 모순을 규칙 기반으로 검사하는 요구가 구체화됐다.
- Basic에서 Pro로의 전환·익스포트, 양 모드의 블록 범위와 Pro 백테스트 범위는 미결이었다.
- 주문하지 않은 판단 로그, 검색, 시스템 장애·재연결 기록이 필수 요구로 제시됐다.
- 기업행사와 시장 이벤트가 백테스트·운영 신뢰성에 미치는 영향이 상세히 정리됐다.

### `회의록_0716_16 (1).pdf` - 2026-07-16 16시

- 과거 데이터는 S3, 한국시간 오전 7시 배치가 잠정 합의됐다.
- 라이브 데이터는 가능하면 초 단위로 Redis를 통해 전달하는 방향을 논의했다.
- 화면에는 초 단위 움직임을 보여주고 완성된 분봉만 영구 저장하는 아이디어가 제안됐다.
- 분봉 영구 저장소, 저장 지표, S3 갱신 방식, 정규장 외 세션과 AWS 구성은 미결이었다.
- 이 내용은 당시 기술 아이디어이며 현재 기술 구조의 확정 사항은 아니다.
