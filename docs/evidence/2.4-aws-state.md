## 이 증거가 정정하는 것

**계획서 §2.4 의 전제가 AWS 에는 맞지 않는다.** §2.4 는 "시장 데이터가 적재되지 않았고,
실제로 쓴 수집기가 30분봉을 버린다" 고 적었다. 앞부분은 **로컬에만** 참이다. AWS 에는 네
해상도가 모두 있고 종목 725개와 manifest 96개가 등록돼 있으며 부트스트랩은
`ALREADY_APPLIED` 다.

`market_hist_script` 가 30분봉을 버린다는 지적 자체는 여전히 유효하다 — 다만 그 스크립트는
AWS 적재 경로가 아니었다. 적재는 `development-market-catalog-bootstrap` 이 했고 30분봉을
포함한다. 따라서 그 스크립트를 적재 경로에서 빼야 한다는 결론은 유지되지만, **긴급도는
훨씬 낮다** — 지금 쓰이고 있지 않기 때문이다.

## 통과하지 못한 것

1. **`feature_materializations` 는 AWS 에서도 0 이다.** §2.5(지표 백필)는 로컬·AWS 양쪽에서
   여전히 미완이며, 이것이 RSI 전략의 실질 차단 요인이다. 종목 725개 × 네 해상도의 백필이
   남아 있다.
2. **`feature_definitions` 가 AWS 에서 1개다.** 로컬은 마이그레이션 적용 후 5개(레거시 1m +
   프로덕션 30m·1h·4h·1d)인데, AWS 는 1개다 — 즉 **AWS RDS 가 최신 마이그레이션을 받지
   않았다.** `V20260808120100__pipeline_seed_production_rsi_timeframes.sql` 이 적용되면 4개가
   추가된다. 백필보다 이것이 먼저다.
3. **RDS 직접 조회는 하지 못했다.** VPC 안에 있어 이 기계에서 psql 이 닿지 않는다. 위 테이블
   수치는 2026-08-05 영수증의 값이며 그 시점의 사실이다. 현재 값 확인은 SSM Run Command 나
   배포 워크플로를 거쳐야 한다.

# 2026-08-08 재확인 — 완료 판정을 이 파일로 옮겼다

## 왜 이 절을 덧붙이나

이 카드의 검사는 로컬 DB 를 보는 `sql-equals` 였고, 정본 데이터는 AWS RDS 의
`idea2strategy_runtime` 에 있다. RDS 는 VPC 안이라 `launch-status.ps1` 의 `DATABASE_URL` 로는
닿지 않는다. 검사가 틀린 답을 준 것이 아니라 **틀린 곳을 보고 있었다.**

그래서 2.4 를 `manual` 로 바꾸고 완료 판정을 이 파일의 존재로 옮겼다. 같은 이유로 2.5 도
`docs/evidence/2.5-aws-feature-backfill.md` 로 옮겼다.

위쪽 §관찰한 결과 는 2026-08-05 시점의 다른 조회(레거시 DB `idea2strategy`)에서 온 값이고,

**이 절의 숫자가 현재 상태다.** 위쪽은 그 시점의 기록으로 남겨 둔다(지우면 왜 오판했는지가
사라진다).
