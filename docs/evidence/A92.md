# A92 — 운영자 풀 MFA 를 ON 으로 복구했다

## 언제 · 어디서

- 2026-08-08. AWS Development, Cognito 사용자 풀 `ap-northeast-2_xxeN2Ej7A`.

## 최종 상태 — 실측

```
UserMFASettingList  : SOFTWARE_TOKEN_MFA
PreferredMfaSetting : SOFTWARE_TOKEN_MFA
MfaConfiguration    : ON
ExplicitAuthFlows   : ALLOW_REFRESH_TOKEN_AUTH, ALLOW_USER_SRP_AUTH
CallbackURLs        : https://ideatostrategy.com/operations/callback
```

세 가지가 모두 원래 자리로 돌아왔다 — 풀 MFA 가 `ON`, 사용자에게 TOTP 기기가 등록되어 선호까지
설정됨, 임시로 켰던 `ALLOW_USER_PASSWORD_AUTH` 제거됨. 콜백 URL 등 다른 클라이언트 설정은
백업에서 복원했으므로 변경되지 않았다.

**그리고 MFA 를 요구하는 실제 로그인이 통과했다.** `https://ideatostrategy.com/operations/login`
에서 인증 앱의 6자리를 넣어 운영자 로그인이 성공하는 것을 확인했다(2026-08-08). 설정만 맞춘 것이
아니라 그 설정으로 로그인이 되는 것까지 확인한 것이다.

## 무엇이 문제였나

풀이 `ON` 이면 Cognito 가 `SOFTWARE_TOKEN_MFA` 챌린지를 주는데, 사용자에게 그 기기가 없었다.
managed login 은 등록 화면(QR)을 주지 않았고, 사용자는 QR 을 한 번도 본 적이 없다고 확인했다.
그래서 **어떤 코드도 통할 수 없는 상태**였다.

나중에 밝혀진 사실이 이 상황을 설명한다. `AdminSetUserMFAPreference` 로 선호를 `Enabled=true` 로
설정하는 것이 **성공했다** — Cognito 는 검증된 소프트웨어 토큰이 없으면 이것을 거부하므로,
사용자가 갖고 있지 않은 기기가 실제로 등록되어 있었다는 뜻이다. 처음부터 챌린지가 뜬 이유가
그것이다.

## 어떻게 풀었나

TOTP 기기를 지우는 API 는 존재하지 않는다. 그래서 **새 기기로 교체**했다.

1. 풀 MFA 를 `OPTIONAL` 로 내려 챌린지를 건너뛰고 액세스 토큰을 얻을 수 있게 했다.
2. 앱 클라이언트에 `ALLOW_USER_PASSWORD_AUTH` 를 임시로 켰다(기존 설정은 백업 후 보존).
3. 사용자가 자기 터미널에서 `initiate-auth` → `associate-software-token` →
   `verify-software-token` 을 실행했다. `"Status": "SUCCESS"` 로 새 기기가 등록되었다.
4. 선호를 `Enabled=true,PreferredMfa=true` 로 설정하고 풀을 `ON` 으로, 클라이언트를 백업에서
   복원했다.

**비밀번호와 TOTP 시크릿은 에이전트를 거치지 않았다.** 3단계는 사용자 터미널에서 실행되었고,
에이전트는 명령 형태만 제공했다.

## 이 과정에서 배운 순서 — 다음에 같은 일을 하면

**`verify-software-token` 이 `set-user-mfa-preference` 보다 먼저다.** 선호를 먼저 켜면 풀이
`OPTIONAL` 이어도 **사용자 단위로 MFA 가 필수**가 되어 다시 챌린지가 뜬다. 이 세션에서 실제로
그렇게 한 번 더 잠겼고, `admin-set-user-mfa-preference` 로 선호를 끄고 나서야 진행할 수 있었다.

## 이 카드가 닫지 않는 것

**MFA 보증 클레임 결함은 그대로 남아 있다.** `docs/evidence/INT05-operator-auth-blocker.md` 에
확정 기록이 있다 — pre-token lambda 가 실제 MFA 수행 여부를 보지 않고
`cognito:mfa-required` 를 붙이므로, backend 의 `OPERATOR_AUTH_ALLOWED_MFA_CLAIM_VALUES` 검사는
어떤 토큰도 걸러내지 못한다.

풀을 `ON` 으로 되돌린 것은 **Cognito 가 MFA 를 강제하게 만든 것**이고, 애플리케이션의 검사가
유효해진 것이 아니다. 지금은 Cognito 설정이 유일한 방어선이며, 그 설정이 다시 드리프트하면
애플리케이션은 눈치채지 못한다. 그 결함은 INT08 소관이다.

## 부수 확인

노출된 값 두 개를 기록해 둔다. 이 세션 중 대화에 노출되었다.

- 운영자 계정 비밀번호 — 사용자가 교체할 것으로 확인했다.
- 첫 `associate-software-token` 의 `SecretCode` — **활성화되지 않았다.** `verify` 를 거치지
  않았고, 이후 새 `associate-software-token` 호출이 그것을 무효화했다. 현재 등록된 기기는 두
  번째 시크릿으로 만든 것이다.
- 액세스·리프레시 토큰 — 액세스 토큰은 5분 수명으로 이미 만료. 리프레시 토큰은
  `revoke-token` 으로 폐기를 요청했다.
