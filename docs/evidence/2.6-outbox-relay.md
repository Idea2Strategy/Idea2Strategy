# 2.6 — AWS 릴리스 후보에서 enable_backtest_outbox_relay = true

## 언제 · 어디서

- 2026-08-08
- 환경: GitHub Actions 리포지터리 변수(AWS Development 배포가 읽는 값)
- 루트 커밋: `83b5c92` (develop)

## 실행한 명령

```bash
gh variable get TF_VARS_JSON | python -c "
import json,sys
d=json.loads(sys.stdin.read())
print('enable_backtest_outbox_relay =', d.get('enable_backtest_outbox_relay','(없음)'))"
```

## 관찰한 결과

```
enable_backtest_outbox_relay = True
```

`TF_VARS_JSON` 은 키 28개를 담고 있고 그중 `enable_backtest_outbox_relay` 가 이미 `true` 다.
`infra/terraform/environments/development/variables.tf:417-421` 의 기본값은 `false` 이며
설명이 "A full release candidate must explicitly set this true" 라고 요구하는데, 배포 변수가
그 기본값을 명시적으로 덮고 있으므로 요구가 충족된다.

그 값은 `templates/ec2-user-data.sh.tftpl:410` 에서
`BACKTEST_OUTBOX_RELAY_ENABLED` 로 호스트에 전달되고, backend-worker 의
`idea2strategy.outbox-relay.enabled` 가 그것을 읽는다.

## 통과하지 못한 것

**런타임 확인은 남아 있다.** 이 증거는 설정값이 옳다는 것까지만 보인다. AWS 에서 전략을
실제로 출시해 `backtest-basic-request` 큐에 메시지가 도착하고 결과가
`backtest.run_outcomes` 에 기록되는 것은 INT03 에서 확인한다 — 이 카드의 범위가 아니다.

세 백테스트 큐 URL 이 배포 환경에서 비어 있지 않은지도 그때 함께 본다. relay 는 빈 URL 인
경로를 조용히 건너뛰므로(`OutboxRelayConfiguration:70-71`), 플래그가 참이어도 URL 이 비면
아무것도 발행하지 않는다.
