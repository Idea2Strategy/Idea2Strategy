# 통합 검증 증거

`docs/launch-readiness-tasks.json` 의 `manual` 작업(INT 카드, A90·A91, 2.6)은 **이 디렉터리에 증거 파일이 있을 때** 완료로 집계된다. `scripts/launch-status.ps1` 이 파일의 존재만 보므로, 내용의 정직함은 리뷰가 지킨다.

## 왜 여기인가

처음에는 `.harness/local/evidence/` 에 두었는데 그 경로는 `.gitignore` 대상이었다. 증거가 각자 기계에만 남아, 한 사람 화면에서는 `[x]` 인 카드가 다른 사람 화면에서는 `[ ]` 로 보였다. 공유 상태를 계산하는 것이 원장의 목적이므로 그것은 결함이었다.

추적되는 경로로 옮기면 두 가지가 따라온다. 완료가 팀 전체에 같은 값으로 보이고, 증거가 **PR 리뷰를 통과해야** 들어온다. 두 번째가 더 중요하다 — 스크립트는 파일이 있는지만 알 수 있고, 그 시험을 실제로 돌렸는지는 사람만 판별할 수 있다.

## 파일 하나에 반드시 들어갈 것

파일명은 작업 ID 와 같아야 한다(`INT03.md`, `A90.md`, `2.6-outbox-relay.md`).

1. **언제 · 어디서** — 날짜, 환경(로컬 조합 / AWS Development), 루트 커밋 SHA 와 서브모듈 gitlink.
2. **실행한 명령** — 붙여넣어 재현할 수 있는 형태로. "확인했다" 는 증거가 아니다.
3. **관찰한 결과** — 명령의 출력, 조회한 행, 화면에서 본 것. 숫자는 숫자로.
4. **통과하지 못한 것** — 있으면 반드시 적는다. 부분 통과를 완료로 적는 것이 지난번 체크리스트가 무너진 방식이다.

## 리뷰하는 사람이 볼 것

실행 명령과 관찰 결과가 없으면 반려한다. 시험을 돌리지 않고 파일만 만들면 원장은 속지만 서비스는 속지 않는다.
